Part 2.1: Create Rays from Cameras

For Camera to World Coordinate Conversion, I first take in the N points and convert it into homogenous coordinates. I then apply the transformation to the homogenous coordinates, then normalize it back to 3D by dividing it by w.

For Pixel to Camera Coordinate Conversion I convert uv into homogenous and then use this formula

pcamera = s · K-1 [u, v, 1]T

where pcamera = (xc, yc, zc) are the camera coordinates, K is the camera intrinsic matrix, (u, v) are pixel coordinates, and s is the depth scale.

For pixel to ray conversion, I extract the camera origin from the camera-to-world matrix. I convert each pixel to camera coordinates at unit depth, transform them to world coordinates, then compute the direction vectors by subtracting the origin. Finally, I normalize these directions to create unit ray vectors.

Part 2.2: Sampling

For sampling rays, I randomly select N indices from the available pixels. I then use these indices to extract the corresponding ray origins, ray directions, and pixel colors from the precomputed arrays.

For sampling along rays, I create evenly spaced sample points between the near and far planes using n_samples points. If random is True, I add random jitter to each sample point within its bin. I then compute the 3D positions along each ray using the ray equation x = o + t·d, where o is the origin, d is the direction, and t is the distance parameter.

Part 2.4: Neural Radiance Field

The network architecture I used was the same as the provided except with one change. I added a relu after the linear layer before it splits off into rgb and depth.

For training, I used the Adam optimizer with a learning rate of 5e-4 and an exponential learning rate scheduler with gamma of 0.9998 applied after epoch 500. This scheduler lowers the learning rate to allow the model to make large updates early in training for faster convergence, then make smaller, more precise updates later.

I trained for 3000 epochs with a batch size of 10,000 rays per iteration, using MSE loss and the PSNR metric/p>

Part 2.5: Volume Rendering

For volume rendering, I implement the given rendering equation. First, I compute alpha values using α = 1 - exp(-relu(σ)·δ), where σ is the density, δ is the step size, and ReLU ensures non-negative densities. I then calculate transmittance using cumulative product of (1 - α). The weights are computed as the product of transmittance and alpha. Finally, I sum the weighted RGB values to get the rendered pixel color.

To render an image, I first create a grid of all the pixel coordinates in the image and convert them to rays using the camera-to-world transformation. I process the rays in batches of chunk_size to manage memory. For each batch, I sample points along the rays, pass them through the network to get RGB colors and densities, compute step sizes between samples, and apply volume rendering to get pixel colors. Finally, I concatenate all the batches into the final image.

To generate the gif of the lego, I looped through the given camera poses, passed it into the render image function described above and generated the images at each pose.
