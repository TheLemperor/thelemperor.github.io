Overview of Project

The goal of this project was to take a digitized Prokudin-Gorskii glass plate image and automatically produce a color image with as few visual artifacts as possible. This was done by splitting the image into the corresponding r, g, b sections, aligning them and then putting them on top of each other.

Approach

Single-scale alignment

Single scale alignment was done by taking in 2 images. One image is translated [-15, 15] in both the x and y direction with steps of 4 each. At each step the image is scored against the other image. This comparison is done with a scoring system, Normalized Cross-Correlation (NCC), which is a dot product between two normalized vectors. The translation with the highest score is kept.

There were issues with the scoring, where the borders of the images hurt my results, so I opted to cut out 20 percent of each side of the image and then run NCC. I originally started out with 10 percent, which worked fine, but to make the algorithm more efficient, I increased it to 20 percent.

The run time is around 18s-19s per jpg image.

Multi-scale pyramid alignment

Multi-scale pyramid alignment was done by first creating an image pyramid for each of the r, g, b images. I implemented a downsampling method which first runs a binomial filter on the image and then decimation by a factor of 2. Each pyramid had 4 total images, the original, and 3 downsampled.

Alignment, using the same method as single scale, was then started at the lowest resolution image. This returned the best offset for that image. This offset was then multiplied by a factor of 2 and applied to the next highest resolution. This is then repeated until all the images with a resolution lower then 3000 in the x is done. This was done so the large images would be sped up by removing the original, but the lower resolution jpg images would still be done with all of them.

The run time is around 40s for the tif files and 2s for the jpg files.

Images that didn't work

The only image that did not work well was emir.tif. This is because the images to be matched for this did not actually have the same brightness values and so ncc did not work properly.
